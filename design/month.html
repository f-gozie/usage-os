Month

A month at a glance — the same day you already know, thirty of them at once. The question this screen answers is not “how much did I work,” it’s “what did that stretch actually look like.” Nothing here scores you.

1 · The screen

Full app chrome, real nav, real date stepper — including the Today button, which is always drawn and simply greys out at the latest range — the same way “next” already does, so the control row never changes width. Hover a cell to see it lift; click goes to that Day.

Asks you to decide Is Month its own nav tab (five tabs), or a zoom control inside Week? Five tabs is honest about it being a real destination; a Week toggle keeps the nav at four and frames it as “same screen, further out.” The board shows the tab version because that’s the riskier one — if the fifth tab feels like clutter to you here, it will feel like clutter in the app.

2 · What goes in a cell

The whole design is this one choice. Three treatments, same five days, same numbers.

A · Mini-dial Recommended

The signature, thirty times. You already read this shape on Day and Week, so there’s nothing new to learn, and the shape of a day survives the shrink — a solid afternoon block still looks different from scattered dipping. Colour stays category-only, which is the one rule that’s bitten us before.

B · Stacked bar

Easiest to compare across days — proportions line up on a shared baseline, and it reads fine at 20px. But it throws away when: a 9am-to-6pm day and a 2am-to-noon day are the same bar. That’s most of what a month is for.

C · Heat block

Legible at any size and the cheapest to build. But it’s the contribution-graph look, and that whole aesthetic is about streaks — the exact thing this product cut on purpose. It also makes colour encode two things at once (hue = category, darkness = hours), which the design system forbids.

Recommendation A, the mini-dial. It’s the only one that keeps “when” — and “when” is the thing a month view can show that Week already can’t. B is the fallback if the dials turn out illegible at real size; that’s what the sliders below are for. C should be ruled out on principle, not on looks — it’s boarded here so the rejection is on the record with a reason.

3 · Every cell state

The important one is the fourth. “Nothing happened” and “we weren’t watching” are different days and must never look the same — right now the app can’t tell you apart, which is how two days went missing without a word.

Needs a ruling The hatch is a new primitive. The design system says “flat fills only — no gradients”; this is a hard-edged 1px stripe (no colour gradation), so it is arguably flat, but it is not in the component list and it would be drift to ship it unblessed. If it survives, it gets written into design-system.md as a component + state. The alternative that needs no new primitive: a dotted --track ring and no cell fill at all.
Copy, locked by this board The hatched cell reads “Not recorded” — not “No data”, not “0h”, not an error colour. It’s a statement of fact about the app, not about you. The month summary counts them plainly: “Not recorded · 2 days.” Hovering says “UsageOS wasn’t running on this day.”

4 · Large text & reduced motion

Same grid at large text, with the load animation off. Figures grow, cells grow with them, nothing clips, and the dials hold their shape because they’re drawn from the cell box rather than a fixed pixel size.

5 · Left open on purpose

Measured — must be resolved before code The R77 ink casing stops working at this size. MiniDial.tsx draws ARC_W 6 / CASING_W 8 in an 80-unit viewBox, so the casing is 1 unit either side — 1.25% of the rendered size. It is a true 1px only at an 80px dial. At 50px it renders 0.63px per side, and R77’s whole mitigation for the Comms yellow on paper quietly stops holding. Either the stroke ratios get parameterised so the casing stays ~1 device pixel at the rendered size, or the cells get bigger. Measured in the browser: at an 80px dial the cells come out 126×130 inside a 984px app frame — so the compliant size fits the existing window width with room to spare. The real cost is height: five rows run 678px, and a six-row month about 813px, so the view scrolls. That is the trade — scroll the month, or break R77. The board now defaults to the compliant size; drag dial size down to 50 to see what the non-compliant version buys you.
Open Does a month need a recap? Day has prose; Week has none today. A month of narrated prose risks becoming a performance review, which is the one tone this product refuses. Boarded here with no recap at all; the four summary tiles carry the facts instead. Say if you want prose and it gets its own round.
Open Six-week months. September 2026 fits in five rows. Months that need six will make the grid taller than the window — either the cells shrink, or the view scrolls. Not solved here.
Not boarded Click-through and keyboard traversal. Cells are clickable in this board but the focus ring, arrow-key movement, and what a screen reader announces per cell all need their own pass before this is buildable.
